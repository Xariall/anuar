# Задача: анализ и унификация договоров «Ауыл-Аманат»

## Контекст

Исходные договоры лежат в `шаблоны МИО/` (17 регионов, структура описана в CLAUDE.md). Цель: определить по содержанию, сколько реально существует типов договоров, сравнить их и подготовить структуру единых шаблонов. Результат будут проверять руководитель и юрист, поэтому каждое утверждение должно проверяться по источнику.

## Общие правила

- Исходные файлы только читать. В `шаблоны МИО/` ничего не изменять, не переименовывать и не конвертировать.
- Для чтения делать текстовые копии в `_work/text/` (LibreOffice headless: `soffice --headless --convert-to txt`), сохраняя в имени регион и исходное имя файла.
- Все результаты сохранять в `_work/analysis/`. Таблицы в `.xlsx`, текстовые выводы в `.md`.
- Ссылка на источник: путь к файлу + номер пункта или раздела (например: `7. ЗКО/договора/Договор займа.docx, п. 4.2`). Если нумерации нет, указывать первые слова пункта. Утверждение без такой ссылки не включать.
- Не придумывать условия, нормы и формулировки. Если условия в документе нет, писать «отсутствует».
- Не выбирать «правильный» региональный вариант. Противоречия фиксировать, но не решать.
- Различие и противоречие разделять:
  - различие: разные значения одного параметра (срок, ставка, размер неустойки и т.п.);
  - противоречие: положения, которые нельзя одновременно включить в один договор, либо пункт, противоречащий другому пункту того же договора.
- Заполненные экземпляры (с наименованием заемщика, суммами, датами) анализировать как шаблон: конкретные данные заменять пометкой `[данные заемщика]`, в реестре отмечать «заполненный экземпляр».
- Дубликаты и версии (`(1)`, `++дата++`, `новый шаблон`): сравнить с соседним файлом. Если текст идентичен, отметить как дубликат и дальше не анализировать. Если отличается, анализировать оба и указать различия.
- Языковые версии: основа анализа русский текст. Казахскую версию сверять с русской только на расхождения по существу и выносить их отдельным списком. Если есть только казахская версия, анализировать ее.
- При большом объеме использовать субагентов (по региону или по типу договора). Итоговые таблицы собирать самостоятельно и проверять ссылки.

## Этап 1. Реестр и классификация

Прочитать все файлы и создать `_work/analysis/01_реестр.xlsx`. Столбцы:

- регион;
- путь к файлу;
- название;
- язык;
- статус: шаблон / заполненный экземпляр / дубликат / версия;
- фактический тип (по предмету договора и ролям сторон, а не по названию);
- назначение;
- связанные договоры (например, залог обеспечивает займ);
- кандидаты на объединение.

Количество типов заранее не предполагать. Критерий одного типа: одинаковый предмет договора и одинаковые роли сторон. Разделение по виду заемщика (ИП, СПК, физлицо) или виду имущества (движимое, недвижимое, будущее) на этом этапе считать вариантами одного типа, окончательное решение принимать на этапе 3.

**После этапа 1 остановиться и показать сводку: список типов, число договоров в каждом, спорные случаи классификации. Не продолжать до моего подтверждения.**

## Этап 2. Сравнительный анализ

Для каждого типа отдельный файл `_work/analysis/02_сравнение_<тип>.xlsx`.

- Строки: разделы и условия, фактически встреченные в договорах этого типа (предмет, сумма, срок, ставка, порядок выдачи, погашение, обеспечение, права и обязанности сторон, ответственность, расторжение, форс-мажор, разрешение споров и т.д.).
- Столбцы: по одному на каждый исходный договор (краткое содержание условия + ссылка на пункт), затем «различия» и «противоречия».
- Условие, которое есть только в части договоров, тоже включать отдельной строкой.

## Этап 3. Унификация

Файл `_work/analysis/03_унификация.md`. Для каждого предполагаемого итогового договора:

- какие исходные договоры в него входят;
- общие положения;
- отличающиеся положения;
- положения, которые необходимо сохранить (региональные положения не удалять только потому, что они отличаются);
- конфликтующие положения: все варианты с источниками, вопрос выносится на решение.

Отдельным разделом: какие договоры нельзя объединять и почему (со ссылками на конкретные положения).

**После этапа 3 остановиться и показать итоговый список унифицированных типов. Не продолжать до моего подтверждения.**

## Этап 4. Структура единых договоров

Для каждого итогового типа файл `_work/analysis/04_структура_<тип>.md`: структура по разделам и пунктам.

- Для каждого пункта указывать источник(и).
- Вариативные пункты оформлять так: `[ВАРИАНТ А: ... (источник)]`, `[ВАРИАНТ Б: ... (источник)]`.
- Региональные пункты: `[РЕГИОНАЛЬНОЕ: регион, источник]`.
- Полный юридический текст не сочинять. Использовать только формулировки из исходных договоров.

## Этап 5. Контроль результата

Файл `_work/analysis/05_итог.md`:

- итоговое количество типов договоров;
- какие исходные договоры относятся к каждому типу;
- какие договоры нельзя объединять и почему;
- основные противоречия;
- положения, по которым требуется решение руководителя или юриста;
- перечень положений с указанием, из какого исходного договора каждое взято.

Перед завершением выборочно проверить не менее 10 ссылок на источники: открыть исходный текст и убедиться, что пункт существует и содержит указанное. Результат проверки добавить в конец файла.
