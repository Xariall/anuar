Проект: унификация договоров программы «Ауыл-Аманат». Результат проверяют руководитель и юрист. Корень: `/home/user/anuar`, рабочая папка: `/home/user/anuar/_work/analysis/tmp/`.

**Структура подтверждена заказчиком 30.09.2026:** шесть итоговых договоров, в каждом «один договор с вариативными блоками». Блоки описаны в `03_унификация.md`, подраздел `N.2` твоего типа.

## Входные данные (только читать)
- `/home/user/anuar/_work/analysis/03_унификация.md`, раздел твоего типа (`N.1`–`N.7`). Здесь состав, вариативные блоки, общие, отличающиеся и сохраняемые положения, конфликты.
- `matrix2_<тип>.json`: выдержки по условиям и договорам `{summary, ref, quote}`. Поле `quote` — проверенная цитата из исходника.
- `/home/user/anuar/_work/text/*.txt`: текстовые копии исходников. Отсюда брать формулировки пунктов (русский текст).
- `register_index.json`: реестр вопросов на решение (`n`, `stage`, `type`, `topic`, `where`). По нему ставь номер вопроса реестра у каждого варианта, который зависит от решения команды.
- `corrections_stage2.json`: подтверждённые поправки к данным этапа 2.
- Исходники в `шаблоны МИО/` не трогать.

## Правила заказчика (обязательны)
1. **Полный юридический текст не сочинять.** Использовать только формулировки из исходных договоров: дословная цитата или близкий к тексту пересказ с пометкой «(редакция по …)». Своих формулировок нет. Если пункт нужен по структуре, но в источниках его нет, писать `[отсутствует в исходных договорах]`.
2. **Для каждого пункта указывать источник(и):** `(№11 Алматы ИП, п. 4.3)`. Если одинаковая формулировка есть в нескольких договорах, перечислить их все или написать «и ещё N договоров: №…».
3. **Вариативные пункты:** `[ВАРИАНТ А: … (источник)]`, `[ВАРИАНТ Б: … (источник)]`. Если выбор между вариантами — вопрос реестра, добавить `— решение: вопрос №X реестра`. Правильный вариант не выбирать, порядок вариантов ничего не означает.
4. **Региональные пункты:** `[РЕГИОНАЛЬНОЕ: регион, источник]`, где условие есть только в одном регионе (подраздел `N.5`). Не удалять.
5. **Вариативные блоки из `N.2`** (вид заемщика, вид имущества, модель сторон и т. п.) оформлять как `[БЛОК <буква>: <вариант> — пункты …]`. Сразу видно, какие пункты включаются при каком варианте.
6. **Данные конкретных сделок** (ФИО, суммы, номера, даты) заменять на `[данные заемщика]`, `[сумма]`, `[дата]`, `[№ договора]` и т. п.
7. **Дефекты исходников** (внутренние противоречия, расхождения каз./рус., ошибочные ссылки) не переносить молча. Если формулировка взята из пункта с известным дефектом, ставить `[ДЕФЕКТ ИСТОЧНИКА: … см. 02_сравнение_<тип>.xlsx]`.

```
Условные обозначения: [БЛОК], [ВАРИАНТ], [РЕГИОНАЛЬНОЕ], [ДЕФЕКТ ИСТОЧНИКА], [данные заемщика], «вопрос №X реестра».

## Вариативные блоки
Таблица: блок | варианты | какие разделы/пункты зависят | источники.

## Преамбула
…

## Раздел 1. <название>
1.1. <суть пункта> — «<цитата или редакция по источнику>» (источник…)
1.2. …

…все разделы по порядку. Порядок разделов выбери по наиболее распространённой схеме среди исходников и поясни выбор одной фразой в начале со ссылками.

## Приложения к договору
Перечень приложений с источниками.

## Нерешённые вопросы, влияющие на структуру
Номера вопросов реестра, которые использованы в [ВАРИАНТ], с темой.

## Проверка
Не менее 5 выборочно проверенных тобой цитат: пункт, источник, «подтверждено по _work/text/…».
```

## Технические требования
- Пиши файл порциями (раздел за разделом), не держи весь текст до конца.
- Цитаты сверяй с текстовыми копиями. Если цитата не находится дословно, перефразируй с пометкой «(редакция по …)» или не используй.
- Пункты группируй по смыслу, но не теряй условия из `N.3`–`N.6`: каждое должно попасть в структуру как пункт, вариант или региональный пункт.
- В ответе верни только: путь к файлу, число разделов, число пунктов с [ВАРИАНТ], число [РЕГИОНАЛЬНОЕ], какие номера вопросов реестра использованы.
