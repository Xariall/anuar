# Этап 2. Инструкция экстрактору (общая)

Контекст: юридический анализ договоров программы «Ауыл-Аманат» (Казахстан). Результат проверяют руководитель и юрист: каждое утверждение должно иметь ссылку на пункт исходного файла. Ничего не придумывать; если условия нет — писать «отсутствует». Не выбирать «правильный» региональный вариант, не оценивать законность, не давать рекомендаций.

## Что читать
- Текстовые копии: /Users/asanaliesmagambetov/Documents/anuar/_work/text/<регион> __ <подпапка> __ <имя без расширения>.txt (ls каталога, имена с кириллицей и пробелами — брать в кавычки).
- Оригиналы (`шаблоны МИО/`) не трогать. Ничего не менять, кроме своего JSON-файла.
- ЧИТАТЬ КАЖДЫЙ ПУНКТ ПОСТРОЧНО и ПОЛНОСТЬЮ (Read с offset/limit порциями). Файлы двуязычные (казахский блок, затем русский, либо параллельные колонки): основа — русский текст; казахский сверять только на расхождения по существу (числа, сроки, ставки, стороны, объем обязанностей) и выносить в `kk_divergences`. Если только казахский — анализировать казахский. Не заявлять, что прочитал, если не читал: если часть файла не прочитана, указать в `notes`, какая.
- Заполненный экземпляр (реальные ФИО/ИИН/суммы/даты/адреса заемщика, залогодателя, гаранта) — анализировать как шаблон: конкретные данные писать как `[данные заемщика]`; нормативные условия, проценты, сроки и размеры неустойки, относящиеся к программе, сохранять как есть.
- Файл может содержать несколько договоров/частей (см. задание): каждую часть размечать в поле `part`.

## Формат ссылки (`ref`)
`<регион>/<подпапка>/<имя файла с расширением>, п. X.Y` (или `разд. N`, `Приложение N, п. X`). Если нумерации нет — первые слова пункта в кавычках: `..., «Заемщик обязан ...»`. Для казахской версии — `(каз.)` после номера.

## Что извлечь — `items`
Для каждого условия, фактически встреченного в договоре, — одна запись:
`{"part": "<часть или пусто>", "topic": "<тема из списка ниже или своя>", "summary": "<краткое содержание с точными значениями: числа, сроки, %, суммы, названия документов>", "ref": "<ссылка>", "quote": "<дословная цитата ≤30 слов, подтверждающая summary>"}`
Одна тема может иметь несколько записей (разные пункты). Ставки, сроки, штрафы, пени, проценты, число дней, размеры — только дословно. Обязательно включать условия, которые встречаются только в этом договоре (региональные особенности, дополнительные пункты): отдельной записью с topic «Особое условие: <краткое название>».
Темы из списка, которых в договоре нет, отразить записью `{"topic": ..., "summary": "отсутствует", "ref": "—", "quote": ""}`.

## Дополнительные поля JSON верхнего уровня (на каждый файл)
- `file`: путь к оригиналу (относительно `шаблоны МИО/`, с расширением); `reg_no`: №(ы) в реестре из задания;
- `status`: шаблон / заполненный экземпляр (и что заменено на [данные заемщика]);
- `kk_divergences`: [{ref_rus, ref_kk, description}] — расхождения по существу между русской и казахской версиями;
- `internal_contradictions`: [{refs:[...], description}] — только если пункт договора противоречит другому пункту ТОГО ЖЕ договора (не «различие», а невозможность одновременного применения; напр. разные суммы/сроки/стороны в разных пунктах, внутренние несоответствия ИП/СПК). Каждое — с двумя ссылками и цитатами;
- `residuals`: остатки чужих данных/дат/названий (напр. «09 декабря 2013 г.», реальные ФИО) со ссылкой;
- `notes`: что не прочитано / неоднозначно.

## Результат
Записать один JSON-файл (UTF-8, ensure_ascii=false; проверить `python3 -m json.tool`) — массив объектов по файлам (по одному объекту на исходный файл, по ключам выше, с `items`), в путь, указанный в задании. В финальном ответе — не более 8 строк: число файлов/пунктов, что не прочитано, самые заметные внутренние противоречия.

## ВАЖНО: как записывать результат (предыдущие агенты зависали на больших записях)
- Не генерируй весь JSON одним вызовом. Работай порциями: прочитал раздел договора → сразу дописал его записи в файл.
- Порядок: 1) создай файл с каркасом (`[{"file":..., "reg_no":..., "status":..., "items":[], "kk_divergences":[], "internal_contradictions":[], "residuals":[], "notes":""}]`); 2) после каждого прочитанного раздела дописывай `items` небольшим python-скриптом (json.load → append → json.dump, ensure_ascii=False), не более ~15 записей за вызов; 3) в конце проверь `python3 -m json.tool` и сверь цитаты (`quote`) с текстовой копией автоматически (подстрока после нормализации пробелов), исправь несовпавшие.
- `summary` — коротко (одно-два предложения), `quote` ≤25 слов.
