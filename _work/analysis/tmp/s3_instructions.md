# Инструкция: этап 3 (унификация) по одному типу договора

Проект: анализ и унификация договоров программы «Ауыл-Аманат» (17 регионов). Результат проверят руководитель и юрист, поэтому каждое утверждение должно иметь ссылку на источник.

Корень: `/home/user/anuar`. Рабочая папка: `/home/user/anuar/_work/analysis/tmp/`.

## Входные данные (только читать)
- `s3_input_<тип>.json`: для каждой строки-условия указано, в каких договорах условие есть (`present_in`) и нет (`absent_in`), плюс готовые тексты «различия» и «противоречия» из этапа 2 со ссылками на пункты.
- `matrix2_<тип>.json`: полные выдержки по ячейкам `rows[условие][метка договора] = [{summary, ref, quote}]`. Используй его, чтобы уточнить формулировку или ссылку.
- `registry.json`: реестр этапа 1 по № договора (статус: шаблон / заполненный экземпляр / версия; стороны; связанные договоры; признаки против объединения).
- `/home/user/anuar/_work/text/*.txt`: текстовые копии исходников. Открывай их, если нужно проверить спорную ссылку.
- Исходники в `шаблоны МИО/` не трогать.

## Правила заказчика (обязательны)
- Не придумывать условия, нормы и формулировки. Если условия нет, писать «отсутствует».
- Каждое утверждение сопровождать меткой договора (например «№11 Алматы ИП») и пунктом, как в данных: `(№11, п. 4.3)`. Утверждение без ссылки не включать.
- Не выбирать «правильный» региональный вариант. Конфликты фиксировать, но не решать.
- **Различие**: разные значения одного параметра. **Противоречие (конфликт)**: положения, которые нельзя одновременно включить в один договор.
- Региональные положения не удалять только потому, что они отличаются: они идут в раздел «необходимо сохранить».
- Заполненные экземпляры анализируются как шаблон: конкретные данные заемщика заменять на `[данные заемщика]`.
- Критерий одного типа: одинаковый предмет договора и одинаковые роли сторон. Варианты по виду заемщика (ИП/СПК/физлицо) и по виду имущества (движимое/недвижимое/будущее) на этапе 3 решаются: оставить вариантами одного договора (вариативные блоки) или выделить отдельный договор. Решение обосновать конкретными положениями со ссылками.

## Что написать
Файл `s3_<тип>.md` (Markdown, по-русски, без воды). Структура строго такая:

```
## <N>. Итоговый договор: <название>

### <N>.1. Входящие исходные договоры
Таблица: № | регион | файл | статус (шаблон / заполненный экземпляр / версия) | вариант (вид заемщика/имущества/модель сторон).
Под таблицей: исключённые дубликаты, если есть.

### <N>.2. Предлагаемая структура итогового договора
Один договор с вариативными блоками или несколько договоров. Коротко объяснить почему, со ссылками.
Если предлагаешь выделить отдельный договор, опиши его здесь (подраздел <N>.2.1 …).

### <N>.3. Общие положения
Условия, которые есть во всех или почти всех договорах и совпадают по существу (допустимы редакционные отличия).
Каждый пункт: суть + в каких договорах (или «во всех, кроме …») + ссылки на пункты.
Общим считать и конкретное значение внутри строки, если оно совпадает везде (например, «штраф 25% за нецелевое использование — во всех, где условие есть»).

### <N>.4. Отличающиеся положения
По условиям: параметр → варианты значений → договоры и пункты. Можно таблицей.

### <N>.5. Положения, которые необходимо сохранить
Условия, которые есть только в части договоров (региональные или особые). Для каждого: суть, договоры, пункты. Пометка [РЕГИОНАЛЬНОЕ], если условие встречается в одном регионе.

### <N>.6. Конфликтующие положения (выносятся на решение)
Нумерованный список. Для каждого: тема; все варианты с договорами и пунктами; «Вопрос на решение: …». Решения не предлагать.

### <N>.7. Что нельзя объединять в этот договор и почему
Договоры или части, которые не входят в итоговый договор этого типа (другой предмет, другие роли сторон), со ссылками на конкретные положения. Если таких нет, написать «не выявлено».
```

Также запиши `s3_q_<тип>.json`: список конфликтов из раздела <N>.6 в формате
`[{"type": "<тип по-русски>", "topic": "...", "question": "варианты со ссылками + вопрос", "where": "03_унификация.md, раздел <N>.6, п. X"}]`.

## Технические требования
- Пиши файл порциями: после каждого раздела дописывай его в файл, не держи весь текст до конца. Так работа не потеряется при обрыве.
- Не копируй целиком тексты «различия» из этапа 2. Сгруппируй и сократи, но сохрани все варианты и ссылки.
- Внутренние противоречия одного договора сюда не переносить, они на листе «Внутренние противоречия» в 02_*.xlsx. Исключение: дефект, мешающий унификации (тогда одна строка со ссылкой).
- В ответе верни только: путь к файлу, число конфликтов в <N>.6, предлагаемую структуру одной фразой.
